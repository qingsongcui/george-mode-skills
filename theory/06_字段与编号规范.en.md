# Field and numbering specification

Protocol: RP-2.0.0  |  Date: 2026-10-15

> English translation of [06_字段与编号规范.md](06_字段与编号规范.md). Field names below match the English workbook ([04_闭环记录工作簿_空白模板.en.xlsx](04_闭环记录工作簿_空白模板.en.xlsx)); the Chinese workbook uses the Chinese names in the original.

## Identity, versions and time

Case IDs use `RP-YYYYMMDD-NNN`, where the date is the local date the dossier was created and same-day sequence numbers do not repeat. Child records use the full case ID plus a suffix: `-AN001` analysis, `-P001` plan, `-EX001` execution, `-OB001` observation, `-PR001` prediction, `-RV001` review, `-UP001` update, `-CL001` closing. Actions may use `-AC001`, metrics `-MT001-v1`. Rules use a library-wide unique `RL-0001` with a separate version. The digits in an ID are identity, not a validity score.

Leave the parent version blank for the first version. Later versions fill in the real parent version. A case may have several historical frozen plan versions; the current plan ID in "Cases overview" uniquely indicates the version currently adopted. Never indicate invalidity by deleting historical plans.

Theory, protocol, rules, goals and plans are versioned separately. Theory and protocol use major.minor.patch; bump major when concept boundaries or record compatibility are affected, minor when adding compatible modules, patch for pure wording or layout fixes. Every substantive adjustment records its reason and effective point.

Date cells must hold real date values. Times in the tables default to Asia/Shanghai; material from other time zones is converted first, keeping the original time zone in the body text. The workbook shows times to the minute; second-precision raw records go in the body or attachments. Times of occurrence, recording, freezing, taking effect and review must never stand in for one another.

## Totals and scoring definitions

1. Spending and time are totaled only from "valid input" records in the Execution log. Corrected and withdrawn entries are excluded; when valid records have input gaps the overview shows "to be checked". With no records it stays blank rather than showing zero. Enter 0 explicitly for zero spending or zero time. If a non-executed entry is logged, spending and time must reflect preparation costs actually incurred, never future budgets.
2. Cash is totaled only in the currency declared for the same case, all as non-negative spending; refunds, income and net returns are registered separately as observation metrics, never as negative numbers in the spending column. Remaining amount = declared budget − registered spending; it is not the actual cash balance or net profit. Budget changes require an update record and a new plan, keeping historical snapshots.
3. "Pre-specified for evaluation = yes" is a human declaration of responsibility and must be backed by an actual frozen file. The sheet cannot detect early leakage of results; even if registration precedes resolution time, a prediction made with the result already known cannot be evaluated as a prior prediction.
4. Brier = (predicted probability − 0/1 outcome)², lower is better. Baseline Brier uses the same event and resolution. Relative improvement = baseline Brier − Brier; a positive number means this entry beats the baseline. A single score cannot prove calibration, causal validity or superiority of the whole theory; when aggregating, first fix the sample set, prediction version and observation window, and report the number of unresolved/withdrawn entries.
5. Input checks only verify some required fields, duplicates and references; they do not verify file content, truthfulness, all approval conditions, cross-row time order or all human categories. They are not a completion certificate. The closed-case hint only checks the closing-file field and the existence of review/update; closing content is reviewed manually according to the manual.
6. Multiple OB references may be separated by Chinese commas (，); formulas do not parse them individually. Background evidence may omit the plan ID. Key unknowns go in the body; do not put text such as "to be confirmed" into cells that require numbers.
7. The predicted probability may be left blank to keep a qualitative prediction, in which case there is no Brier score. Only valid rows that are resolved, have a numeric outcome of 0 or 1, have a resolution time/OB and were pre-specified are scored. Early stops, withdrawals or undeterminable cases keep their reasons and are not selectively deleted.
8. Each sheet holds 300 records. Beyond that, extend the table, formulas, validation and all reference ranges together; or open a new volume and maintain volume numbers and a cross-volume index in the project index, keeping the old volume.
9. The check column of each input sheet serves that sheet's input handling; the overview reads its valid records. The Reviews and Update log sheets reference each other's IDs, but formulas do not reference each other's computed results, avoiding circular calculation.

## Record ownership

Analysis, plan commitments, reviews, updates and rule text are kept in project Markdown files. Executions, observations and predictions may first be registered in the workbook; the Markdown only records their IDs and snapshot paths. Each fact maintains only one original place of registration; corrections add new records citing the old ID. When freezing, save a copy of the related workbook as well.

## Scope of verification

Before delivery, the generation tool's calculation engine was used to check blanks and zeros, budget and time totals, multiple records, duplicate and orphan IDs, review due dates, prediction scores and some missing closing items, and each sheet's preview was checked. It has not yet been verified by actual use in the user's local Excel or WPS; on first opening, keep automatic calculation on and check one complete record of your own.
