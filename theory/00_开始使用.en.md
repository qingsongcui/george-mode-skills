# Reflexive Practice Loop Toolkit

Version: 2.0.0    Date: 2026-10-15    Default time zone: Asia/Shanghai (UTC+08:00)

> English translation of [00_开始使用.md](00_开始使用.md). Links point to the Chinese originals; each has an `.en.md` English sibling.

This set of files supports doing the following continuously: case intake, full theoretical analysis, settling on a plan, pre-registration, execution and observation, review and attribution, dynamic updating, and rule distillation.

## First use

1. Read "How one case goes through the loop" in the [operating manual](02_闭环运行手册.md).
2. Copy the [project dossier templates](05_项目档案模板/) into your own project directory and assign a case ID, e.g. generated by the `RP-YYYYMMDD-NNN` numbering rule; example IDs do not mean a real project has been set up.
3. When analyzing a new case, provide the [full theory text](01_反身实践私典_理论全本.md), the [AI collaboration instructions](03_AI协作指令.md) and the project dossier together.
4. Complete the full analysis, settle on a plan and save the prior version. If something has not been executed, write "not executed"; for unknown data write "to be confirmed".
5. Append execution and actual results to the records. After review, produce an update record; if something changed, generate a new version; if not, record the reason for keeping it.
6. Use the [blank workbook template](04_闭环记录工作簿_空白模板.xlsx) (English version: [04_闭环记录工作簿_空白模板.en.xlsx](04_闭环记录工作簿_空白模板.en.xlsx)) to manage multiple cases, numeric records, review dates and the version index.

By default every new case gets a full analysis. Later feedback checks all modules for changes and expands the parts that changed; when key conditions change, redo the full analysis.

## Files and purposes

| File | Role |
|---|---|
| 01 Full theory text | The independent, complete theory text, with no fictional cases |
| 02 Loop operating manual | Order of operations, file relationships, freezing, review, update and closing |
| 03 AI collaboration instructions | Working rules to hand directly to an AI, plus kick-off instructions for each phase |
| 04 Blank workbook template | Multi-case index, plans, actions, evidence, predictions, reviews, updates and rules sheets |
| 05 Project dossier templates | Nine copyable Markdown templates to fill in |
| 06 Field and numbering specification | IDs, versions, times, statuses, references and field ownership |
| 07 Theory sources and revision notes | Scope of revision, retained logic, references and items still to be verified |

## Authoritative home of records

The project Markdown dossier is the authoritative text for analysis, plan commitments, review conclusions and update rationale. The workbook stores the cross-case index and structured logs; its summaries of plans cannot replace the frozen text.

Executions, observations or predictions may be registered for the first time directly in the corresponding workbook sheet. The corresponding Markdown log only cites the ID and file; copying them again is not required. At review or settlement time, save a cut-off snapshot of the relevant workbook, or export the relevant rows and keep the original file; record the snapshot's location so future edits do not affect past evaluations.

Each piece of data has only one original place of registration. Corrections must add a new record citing the original ID; never maintain conflicting values independently in several places.

## What to provide each time you continue work

- The theory version and the AI collaboration instructions.
- The current project's `00_项目索引.md` (project index).
- The currently valid analysis, the frozen plan, and the previous review and update record.
- Newly added facts, execution records, observation IDs and original attachments.
- When structured logs are involved, the current workbook and any necessary historical snapshots.

The AI cannot assume it permanently remembers all files across sessions. Historical records not provided should be marked "to be obtained", not filled in by the AI.

## File-keeping conventions

Each project keeps working drafts and an `归档/` (archive) folder. Working drafts can be edited; after settlement, review and update are complete, save a numbered version snapshot. The index points to the latest valid version; old versions are kept.

All record templates in the toolkit are blank. No real business data, execution results or approved decisions have been filled in on anyone's behalf. Workbook formulas only help organize, remind and calculate; they never make theory revisions automatically.
