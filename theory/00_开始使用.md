# 反身实践闭环工具包

版本：2.0.0　　日期：2026-10-15　　默认时区：Asia/Shanghai（UTC+08:00）

这套文件用于持续完成：问题输入、理论完整分析、方案定案、事前留档、执行观测、复盘归因、动态更新与规则沉淀。

## 第一次使用

1. 阅读 [运行手册](02_闭环运行手册.md) 的“一个问题怎样走完闭环”。
2. 将 [项目档案模板](05_项目档案模板/) 复制到自己的项目目录，赋予一个问题编号，例如按 `RP-YYYYMMDD-NNN` 编号规则生成；示意编号不代表已经建立真实项目。
3. 新问题分析时同时提供 [理论全文](01_反身实践私典_理论全本.md)、[AI协作指令](03_AI协作指令.md) 和项目档案。
4. 完成全量分析，确定方案并保存事前版本。未执行就填写“未执行”，未知数据填写“待确认”。
5. 将执行和实际结果追加到记录中。复盘后形成更新单，有变化则生成新版本，无变化则记录保留理由。
6. 使用 [记录工作簿空白模板](04_闭环记录工作簿_空白模板.xlsx)（英文版：[04_闭环记录工作簿_空白模板.en.xlsx](04_闭环记录工作簿_空白模板.en.xlsx)） 管理多个问题、数值记录、复盘日期和版本索引。

默认每个新问题都做完整分析。后续反馈对全部模块检查变化，展开有变化的部分；关键条件改变时重新完整分析。

## 文件与用途

| 文件 | 作用 |
|---|---|
| 01 理论全文 | 独立完整的理论正文，不含虚构案例 |
| 02 闭环运行手册 | 操作顺序、文件关系、冻结、复盘、更新与结案 |
| 03 AI协作指令 | 直接交给AI的工作规则与各阶段启动指令 |
| 04 记录工作簿空白模板 | 多问题索引、方案、行动、证据、预测、复盘、更新与规则表 |
| 05 项目档案模板 | 九份可复制填写的Markdown模板 |
| 06 字段与编号规范 | 编号、版本、时间、状态、引用和字段归属 |
| 07 理论来源与修订说明 | 修订范围、保留逻辑、参考文献与尚待验证事项 |

## 记录的权威归属

项目Markdown档案是分析、方案承诺、复盘结论和更新依据的权威正文。工作簿保存跨问题索引与结构化流水；其中对方案的摘要不能替代冻结正文。

执行、观测或预测可以直接在工作簿相应表中首次登记。对应Markdown日志只引用编号和文件，不要求重复抄写。复盘或定案时将相关工作簿另存一份截止时点快照，或导出相关行并保存原文件；记录该快照位置，避免未来修改影响过去评价。

同一条数据只选一个原始登记处。更正必须新增记录引用原编号，不能在多处独立维护互相冲突的值。

## 每次继续工作时提供什么

- 理论版本和AI协作指令。
- 当前项目的 `00_项目索引.md`。
- 当前有效的分析、冻结方案及上一份复盘和更新单。
- 本次新增事实、执行记录、观测编号及原始附件。
- 涉及结构化流水时，提供当前工作簿及必要的历史快照。

AI不能假定跨会话永久记得所有文件。没有提供的历史记录应标记待获取，不应自行补全。

## 文件保存约定

每个项目保留工作稿和 `归档/`。工作稿可以编辑；定案、复盘与更新完成后保存带编号的版本快照。索引指向最新有效版本，旧版本继续保留。

工具包中的所有记录模板均为空白模板。没有代填真实业务数据、执行结果或已获批准的决定。工作簿公式只帮助整理、提醒与计算，不会自动作出理论修订。
