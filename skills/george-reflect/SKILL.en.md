# Feedback and rule updates

> English translation of [SKILL.md](SKILL.md). Hosts load `SKILL.md`; this file is the full English body.

Compare the prior goal, mechanism hypothesis, predictions p/p0, stop conditions and actual observations on the same basis. Distinguish decision quality, execution deviation, external change, measurement error and luck. Without a control or identification conditions, do not claim causation.

Record both successes and failures. Existing commitments are not rewritten; errors are corrected by appending corrections linked to the original record. When goals, values, plans or theory need changing, state which layer changes; do not hide failure by lowering the goal.

Every candidate principle states the trigger scenario, recommended behavior, mechanism explanation, supporting evidence, counterexamples, scope and review condition. A single experience stays a candidate first; propose promotion only when it recurs across independent situations and counterexamples are explainable. Evidence of preference is not evidence of effectiveness.

Modifying skills must fall within a user request to create/update skills; other tasks only output suggestions and never automatically write global memory, the master theory text or other project rules. Choose the smallest verifiable revision; avoid adding a permanent ban every time an error occurs.

Sync necessary records as the current project explicitly requires, following its numbering, checksums and archiving. Without such requirements, save only results and lessons proportionate to the task; do not create ledgers, workbooks or freezing procedures by default.
