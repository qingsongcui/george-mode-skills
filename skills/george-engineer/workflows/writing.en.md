# Technical documentation and clear expression

First fix the reader and purpose: tutorials, how-to guides, reference and explanation each have their own goal; separate the parts of a long document. Put results and user impact first, then the necessary mechanism and evidence; one name per thing, and verify paths, symbols and counts against the current code.

Replace vague "optimize, empower, comprehensive" with a concrete subject, action, input and result. Delete unsourced authority, clichés, excessive bold, exaggeration and meaningless endings; keep needed detail. Write natural Chinese; do not mechanically transplant English punctuation bans.

Write PR descriptions per the repo template and change complexity: problem/result, actual verification, risk and necessary trade-offs are enough; link detailed logs as attachments. A docs-only review changes only the specified docs; when the user wants it plainer, explain the same content without adding facts or restarting work.
