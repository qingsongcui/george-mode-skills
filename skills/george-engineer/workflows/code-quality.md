# 行为测试、类型与代码整理

## 测试

用户明确要TDD，或故障有廉价明确本地复现时：写最小行为测试→实际确认因目标行为错误而失败→最小修复→同测试通过→相关回归。编译失败、依赖缺失或测试写错的红灯不算原问题被复现。昂贵复杂测试用最近的真实可执行检查，不为单行文案凑测试。

检验一个测试：故意破坏返回值/副作用/去重时应失败；只重构内部结构而行为不变应通过。不要从被测代码算期望，不通过松泛truthy断言伪造覆盖。负例最好配正例，证明观察器能看见该行为。

## 结构与TypeScript

先用状态机、判别联合、表/注册表、领域模型消除非法组合；外部数据在边界解析，内部使用可信契约。并发或持久状态改变了保证时重新校验。TypeScript优先推导权威schema、穷尽switch、语义ID品牌；消除无依据any/as/non-null断言。类型只加强到避免真实部分函数/非法状态所需，别炫技。

## 审阅前整理

读最终diff，删无证据的防御、单调用者无价值包装、重复状态、空抽象、调试遗留、AI模板话。注释保留代码无法表达的非显然原因、接口契约及必要许可，不执行“一律删注释”。复杂改动由没写它的人再看。修剪后运行相关检查，不把语言整洁当功能验证。
