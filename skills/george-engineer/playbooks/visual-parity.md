# 视觉等价迁移

1. 改动前建立真实截图基线，覆盖组件状态、视口、字体、主题、数据和动画时刻；匹配两实现则同条件截图。没有基线不能声称等价。
2. 固定比较器、渲染环境、掩码和阈值。要求 pixel-exact 时阈值为零；无法避免的渲染噪声只能事前用重复基线确定容差及解释，不能出差异后放宽。
3. 共享原语先迁并验证，再按组件隔离所有权。每次迁一个安全单元，运行图像 diff 并查看差异区域，不能只凭肉眼或总分通过。
4. 不改基线、不遮住失败区域、不通过重构比较器制造通过。若用户确要新视觉，明确转变验收契约并建立新的批准基线。
5. 同时驱动关键交互和可访问状态。图像相同不证明事件、焦点、错误与加载状态正确。
6. 交付每个组件的比较结果、图像/差异图、环境与剩余项，进入 PR 交付。
