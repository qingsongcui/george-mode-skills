# 受控迭代优化

1. 明确现实负载、单一主指标、方向、回归底线、预算和可检查停止条件。若使用最少尝试数，事前按研究需要确定；不要机械固定十次。无法重现投诉先修复测量任务。
2. 创建可重跑测量工具，用容易与困难负载证明灵敏度，再冻结工具、数据、指标与基线。输出错误和工作量；重复采样以中位数/分布评估噪声。读 [测量审计](../../george-evaluate/workflows/benchmark.md)。
3. 建 decision.tsv，每次记录 id、机制假设、基准、改动、前后值、分布、回归、保留/撤销、理由。每次先读旧行，避免重复失败。
4. 每轮只改变一个可解释机制；多假设竞争用独立 worktree 和相同测量条件。实现可以委派，指标与裁决由负责人掌握。未测量改动不能叠加。
5. 只有提升超过噪声且回归通过才保留，否则撤销本轮自己的改动。每个接受的改动形成独立可验证单元。简化代码且不损指标也可保留，但标注为简化，不能算性能收益。
6. 平台期换假设类别、重看机制、检查测量工具；不盲目重试。目标达到、预算耗尽或剩余收益低于成本时按事前规则结束；保留未达成状态，不放宽目标伪造成功。
7. 最终全量相关回归，汇总尝试及舍弃原因。无人值守时只借 [持续运行](../../george-orchestrate/playbooks/autonomous-run.md) 的唤醒机制。
交付：冻结基线和目标、最终值、保留/撤销次数、决定日志、未试假设和停止理由。
