# 重构与迁移

进入条件：结构改变、行为保持。发现新功能或已有缺陷单列，不能默默混进等价性目标。
1. 在结构移动前固定行为契约。用真实输入输出、characterization test、快照、回放或等价工具记录旧行为；lint/typecheck 不能代替行为基线。
2. 画出现有调用者和目标数据结构，说明新结构减少哪些分支、非法状态、追踪层数或隐藏状态。无此收益，保持直白代码。
3. 读 [设计竞争](../../george-design/workflows/architect-arena.md) 比较必要的结构选择。大范围迁移用 [定制运行](../../george-orchestrate/workflows/figure-it-out.md)，先减死代码再建必要基础。
4. 按小步迁移，每步保持行为基线。枚举代码、字符串、配置、文档、序列化和动态调用者；逐个读回重命名。内部消费者可同步迁移时迁完删旧 API，不积累双路径。
5. 外部消费者或线上数据确需兼容时写分阶段迁移、观测、回滚与旧 API 删除条件。隔离分支内可暂时不可构建，但不能把这种状态当可发布单元；明确恢复完整验证的边界。
6. 在真实产物上比较旧新输出，测必要性能，检查依赖方向与持久化兼容。证明等价后才宣称行为不变。没有降低阅读负担的抽象撤回。
7. 交付顺序体现证据：行为基线→减法→结构迁移→清理；按 [PR交付](opening-a-pr.md) 处理需要的版本交付。
交付：保留的行为、结构收益、等价证据、迁移和回滚状态。
