# 故障修复

进入条件：修复被报告的错误。先把错误运行出来，不能只凭源码猜。
1. 在用户发生问题的同一种入口复现，记录版本、输入、状态、错误及最小触发条件。能控制的先亲自操作；只有目标表面确实不可达才说明原因请用户补证据。
2. 结合 [how/why](../../george-design/workflows/how-why.md) 建立候选机制。每次选最能区分假设的观察，二分缩小范围；必要时加临时日志、计数器、trace。重启才出现的错误先查持久状态。
3. 追到第一个错误状态产生点。合法状态没处理就在该边界修；非法状态被制造则修制造点，不能靠吞错、钳制、无限重试掩盖。连续两次失败共享同一前提，先检验那个前提再尝试补丁。
4. 证据支持机制后设计最小修复。跨边界、有多种结构选择时进入 george-design；将实现和审查分开。机械改动可委派，主负责人核对 diff 与原始复现。
5. 有便宜本地测试路径时按 [TDD](../workflows/code-quality.md) 先留下失败的行为测试，再修复并重跑。同样条件下原始表面必须由失败变通过，保留前后输出；测试不能自造期望证明自身。
6. 搜索同一错误模式的其他实例，修范围内受影响者。移除失效假设产生的补丁、临时调试与无效防御。执行相关回归，按 [PR交付](opening-a-pr.md) 收尾。
交付：触发、根因、修改、同表面前后证据；未能复现时只能称假设性修复。
