# 一次性能问题

1. 使用现实负载在正确入口捕获基线 trace。记录数据量、历史、状态、并发、缓存、完成工作量、错误数、时钟与环境。先读 [测量审计](../../george-evaluate/workflows/benchmark.md)。
2. 从热点与系统计数器定位限制因素，说明为什么不是更快两倍；不能由源码想象性能上限。用 how 调查机制，按成本顺序尝试：不做无用工作→不重复→降低频率→推迟→移出关键交互→并行→单次更便宜。
3. 一次一种机制改动。必要时做架构比较；实现与审查分开。保持测量工具固定，捕获后置 trace，与基线同口径比较。
4. 解析大 trace 为可查询表，比较热点、端到端延迟、工作计数、错误与资源成本。排除缓存命中、跳过工作、客户端瓶颈、单边参数未调优、噪声。
5. 达到目标即停；错误或回归则撤回。长期迭代转 [爬坡](hillclimb.md)。按 [PR交付](opening-a-pr.md) 保留测量命令和证据。
交付：基线→结果、单位、样本数/离散度、机制及端到端影响；小样本不宣称普遍提升。
