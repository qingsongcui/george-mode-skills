# 生成与维护项目专属验证能力

## 建立

1. 查项目源码、运行文档、包脚本与真实界面，确定能启动什么、怎么驱动、观察什么、隔离什么。列用户最重要的三到五个功能，按真实动作建立功能地图；别按源码文件名代替用户功能。
2. 在项目允许目录创建verify说明与最小工具。包含launch、doctor、drive、evidence、cleanup及必要helpers。写实际命令、端口/进程识别、测试账号/数据来源、选择器或CLI输入、期望可见结果；不得填猜测选择器。
3. doctor检查目标进程/版本/端口/健康与隔离状态；不能把旧服务或缓存截图当本轮实例。drive同时验证动作、结果、存储或外部副作用。证据含时间、版本指纹、输入、结果、输出路径。
4. 至少真实跑通 launch→doctor→一个功能→保存证据→cleanup，再检查证据仍存在。只清理本轮创建的进程/隔离数据，不杀所有同名应用。失败或超时也执行恢复和清理。
5. 可用本包 [验证运行器](../scripts/run_verification.py) 执行显式步骤合同，示例见 [合同模板](../templates/verification.json)。命令来自项目发现，不从模板编造。长驻服务由专用launch/cleanup配对管理。

## 维护

先读功能地图，按源码差异找所有受影响功能；授权时并行只读调查，每项回报变化。负责人在实际环境逐个drive所有承诺覆盖功能，失败先doctor/重置并定位。

结果标 clean/changed/blocked。维护任务只改验证技能与脚本；产品缺陷单列，不能弱化阈值、改截图基线或删步骤让它通过。清理后证据再次可打开才记完成。

独立验证者拿已固定版本、相同合同和隔离环境，不修改实现或验收标准。CLI成功但正文失败、产物失效、非成功终态、错误控制对象均判失败。
