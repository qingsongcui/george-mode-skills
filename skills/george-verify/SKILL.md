# 按真实结果验收

先明确本轮承诺的是哪一层结果，再选对应检查。

| 结果层 | 所需证据 |
|---|---|
| 本地文件或包 | 内容、依赖、链接、打开或解压结果；视觉成品必须渲染检查 |
| 代码行为 | 实际调用路径及关键失败路径；有意义的测试或最小复现 |
| 模型与配置 | 目标宿主真实最小请求及准确错误；设置保存或模型列表不足以证明可用 |
| 宿主适配 | 技能发现/加载、任务执行、宿主产物分别验；需要非交互控制时另验控制入口 |
| 平台写入 | 正确账号和对象、提交回执及实际状态重新读取 |
| 使用与商业效果 | 真实外部使用、采用、付款或利润证据，排除自测与重复统计 |

未执行的检查写未验证。工具退出 0 不能覆盖正文失败、超时或错误终态。没有可见状态时先恢复可观测性，再操作。

结果未知的发送、发布、订单或资金操作不得盲目重试。先按对象标识、时间窗与历史状态对账；无法判定则保留 unknown 与恢复条件。

多宿主报告分“文件已安装、加载已验证、真实任务通过”，不能互相替代。所需真实调用若超出当前授权或会产生未知费用，保留未验并说明具体缺口。

记录检查方法、时间、结果和局限。项目要求 EX/OB、工作簿及冻结校验时一起完成，不能把记账完成当作业务成效。

## 项目级验证工具

需要反复驱动软件时，执行 [项目验证生成与维护](workflows/project-verification.md)。记录绑定head/内容指纹的证据；独立verifier不能由作者冒充。持久结果用 [编排工具](../george-orchestrate/tools/README.md) 记录。
