# 原型裁决

1. 写明原型要裁决的具体问题：布局、密度、交互、行为、时序或可行性。没有选择要裁决则回功能开发。可实测的事实分歧先做观察；产品偏好仍由用户决定。
2. 方向开放时收集可引用参考并提出实质不同的两到三个方向；用户已定方向不重开选择。用最轻的栈在独立 scratch 目录制作，不能修改生产基线。
3. 视觉方案放在同一切换器内对比；行为方案使用同一输入和度量。原型允许粗糙、无抽象，但不得污染业务数据或泄漏凭据。
4. 在匹配表面实际操作、渲染、截屏或测量。证明原型真的触发所比较行为；图好看不证明可交互，时序模拟不证明线上性能。
5. 给出证据、取舍与推荐，保留可打开的原型。选定后由 [功能剧本](../../george-engineer/playbooks/feature.md) 正式实现，不把试验代码直接称生产成品。
交付：待决问题、各方案、观察、推荐与原型路径。
