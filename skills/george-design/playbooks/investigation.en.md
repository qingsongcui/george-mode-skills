# Read-only investigation and explanation

1. State what needs explaining; use [how/why](../workflows/how-why.md) to separate the current mechanism from historical motive. For non-code evidence use [George investigate](../../george-investigate/SKILL.md).
2. Build a verifiable explanation along the authoritative entry points, real call paths, configuration and historical evidence. Group independent sources; trace historical summaries back to the original source; keep unknowns.
3. Output the overall role, core concepts, flow, file locations and boundaries; for a choice question, give an evidence-based trade-off comparison. Point out a wrong premise directly.
4. Investigation does not trigger implementation, PRs or monitoring. Hand off to the matching playbook only when the original task explicitly includes follow-up implementation; otherwise finish with a cited answer.
