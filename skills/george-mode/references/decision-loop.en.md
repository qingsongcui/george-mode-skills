# Decision loop (self-contained reference)

This page is all the decision method george-mode needs to run; it depends on no external theory files or private ledgers. It describes a general "reflexive practice" loop: first write judgments as commitments reality can overturn, then execute, observe, review and update within bounds.

## Loop overview

```
Case and materials → analysis → plan and pre-registration → conditions for implementation clear?
   No → back to analysis
   Yes → freeze (save a snapshot of the prior commitment) → execute → observe → review and attribution
        → change the judgment or plan? Yes → update and form a new version → back to analysis
                                       No → record reasons for keeping it and the next observation point
        → close the case and state remaining responsibilities
```

"Freezing" only saves the prior commitment; it does not stop learning, nor does it allow rewriting the past afterwards to hide changes.

## 1. The five registration elements

For important or irreversible decisions, write down before executing:

| Element | What to make clear |
|---|---|
| Goal | Who decides, what outcome is pursued, deadline, available time/money, consequences that cannot be borne; what the user has already decided |
| Assumptions | The mechanism assumptions the plan depends on, written as observable statements; distinguish facts, user reports, inferences and unknowns |
| Falsifiers | Which observations would show the assumption is wrong; keep at least one competing explanation |
| Predictions | Metric definition, unit, direction, baseline, observation window, data source; when probabilities can be given, write the main probability p and reference p0; when they cannot be given reliably, keep a qualitative judgment |
| Stop conditions | Risk ceiling, budget, review checkpoints, conditions to stop/withdraw/double down/escalate |

At the same time compare feasible routes with "keep the status quo"; never pass off a route the AI prefers as the user's choice; plans not adopted are labeled "suggestions".

## 2. When analysis counts as complete

The analysis output contains together: fact boundaries, value goals, actor conditions (resources, capabilities, authorization), causal assumptions, competing explanations, implementable interfaces, baseline and alternatives, rationale for trade-offs, risk boundaries, execution plan and feedback arrangements.

It can be organized by the following modules (for a module that does not apply, write "not applicable" and the reason; do not invent content):

1. Define the case and deadline
2. World structure and constraints (check the live situation; do not substitute old state for current state)
3. Actors, resources and position
4. Values, goals and bottom lines
5. Required capabilities and structure
6. Interfaces and other parties' likely reactions
7. Competing hypotheses and causal audit (trace original sources; same-source counts as one evidence group)
8. Candidate levers
9. Value of information, value of action and risk (reversibility first)
10. Action phases and governance (who authorizes, who executes)
11. Observation, attribution, calibration and evolution

When a unique ranking is impossible, state the value choice or key unknown the recommendation depends on, and give a concrete information-gathering action, a minimal commitment, or an explicit decision to wait with a deadline. "Keep researching" cannot replace a concrete action, and numbers must never be fabricated to fill gaps.

## 3. Pre-freeze checks

1. The analysis version and information cut-off time are clear.
2. The chosen plan and executable actions are clear.
3. Metric definition, baseline, window and data source are handled; for missing items, explain why they do not affect the current action.
4. Risk ceiling, budget, review checkpoints, stop and escalation conditions are clear.
5. Executor, decision-maker and scope of authorization are clear; suggestions are not confused with adopted decisions.
6. Key predictions are registered before results are revealed.
7. The snapshot is saved in a location that can be read back.

If the action already happened and the record is added afterwards, label it honestly as a "retroactive entry"; it does not gain the evidential status of a prior prediction.

## 4. Execution and observation

Record raw results first, then write interpretations. Each observation keeps at least: time of occurrence, time recorded, corresponding plan, actual action or metric, value and unit, source, quality status. Corrections add a new record pointing to the original rather than deleting it. When an external operation's result is unknown, reconcile first; do not resubmit.

## 5. Review order

Check data and execution → compute achievement against the **original** goal → check counterfactuals and competing explanations → distinguish random fluctuation, execution deviation, environmental change, mechanism error and goal misfit → only then evaluate current value and next actions.

Outcome states can be: achieved / partially achieved / not achieved / not yet due / undeterminable. Causal states can be: change observed / mechanism supported / limited causal support / insufficient evidence. One negative result does not automatically refute a mechanism, and one positive result does not prove a method is generally effective.

## 6. Updates and rule distillation

Every review produces an update record (including "keep unchanged"): old value, new value, basis, scope of impact, decision-maker, effective time, next verification. When the action needs to change, first form a new plan version and save a snapshot, then switch the "current plan" pointer.

Promoting experience into a rule does not happen automatically by success count: review the independence of evidence, failure records, counterexamples, environmental differences and value relative to the baseline; rules state their scope and review conditions.

## Depth tiers

Simple, low-consequence, reversible matters may use the lightweight path, but state which modules were omitted and why. High-consequence, irreversible or goal-conflicting new cases use full analysis. Routine sub-actions under an already frozen strategy register only the real increment.

## Four kinds of validity, checked separately

Conceptual, empirical, procedural and normative validity are judged separately. A complete log does not prove improved results; format cannot replace judgment.
