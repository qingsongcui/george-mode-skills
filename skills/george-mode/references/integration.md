# George 接入合同 0.3.0

pstack（Lauren Tan / @poteto，MIT，https://github.com/cursor/plugins/tree/main/pstack）的23剧本、24原则及配套专门工作流是功能来源；本包内改造后的文件是执行入口，署名见包根 NOTICE.md。George 保留完整操作机制，改变触发强度、授权假设与宿主绑定。

## 深度决定如何用，不决定有没有

- 轻量：自包含小任务，直接交付和相关核对。
- 标准工程：调查调用链→必要设计→实现→真实表面验证→审查→交付。相关步骤不能因“轻量”省略实证要求。
- 复杂/高后果：竞争设计、独立审查、行为评测、项目验证工具、依赖编排和恢复记录全部可用。高后果现实取舍接 george-decide，重要预测事前登记。
- 长期项目：复用上述能力，加持久状态、单一写入者、依赖图、版本绑定验证、停止和续接。

## 委派与宿主

George 工作流在复杂设计竞争、独立审查、分区调查及盲测时要求独立子代理，前提是用户已调用本模式、宿主允许委派并有工具。简单任务不强制多代理。每个代理必须知道自己并非唯一写入者，不回退他人改动，并收到所有权、证据、验收和禁改范围。

没有委派能力时串行执行并明确标为自审；需要独立审查的高后果发布门槛仍是未满足，不能改名通过。启用George时按宿主选择本轮子agent：Codex依[Codex自主调度](../../george-orchestrate/adapters/codex.md)；Cursor依[Cursor自主调度](../../george-orchestrate/adapters/cursor.md)；Grok Build / `grok` CLI依[Grok自主调度](../../george-orchestrate/adapters/grok.md)；Google Antigravity依[Antigravity自主调度](../../george-orchestrate/adapters/antigravity.md)；其他宿主沿用实际模型设置。允许可获得的不同模型做交叉评审，禁止擅改全局配置或冒称多模型。

审查者独立读取事实；同源证据或同一模型的共识不能代替真实运行。

## 改造规则

可逆且已授权的工作直接完成。对外消息、发布、支出、合并/部署遵守本轮明确授权；不使用 Poteto 的宽泛外部行动默认。不要重置未知工作区、删除未归档工作、自动改理论/全局记忆。用户指定的产品和目标保持。

复杂任务有独立产物才并行；主代理负责核验与共享状态。项目源码与持久默认模型配置保持；Codex、Cursor与Grok本轮派工参数可按各自自主调度适配器选择。工具缺失选可验证替代；不可验证就写缺口，不以软件存在冒称能力生效。

输出只保留影响决定的事实、依据、变化、验收和未完成项。原则不强制逐条报名字，不套英语标点限制。PR按仓库模板和当前完成度处理，未完成可用draft；不为只读解释或本地成品强制创建PR。
