# 决策闭环（自包含参考）

本页是 george-mode 运行所需的全部决策方法，不依赖任何外部理论文件或私有台账。它描述一种通用的“反身实践”闭环：先把判断写成可被现实推翻的承诺，再执行、观察、复盘和有边界地更新。

## 闭环总览

```
问题与资料 → 分析 → 方案与事前登记 → 实施条件明确？
   否 → 回到分析
   是 → 冻结（保存事前承诺快照）→ 执行 → 观测 → 复盘与归因
        → 改变判断或方案？ 是 → 更新并形成新版本 → 回到分析
                           否 → 记录保留理由与下次观察点
        → 结案并写明剩余责任
```

“冻结”只是保存事前承诺，不是停止学习；也不允许事后改写过去来掩盖变化。

## 一、登记五要素

重要或不可逆的决定，在执行前写下：

| 要素 | 要写清什么 |
|---|---|
| 目标（Goal） | 谁决定、要争取什么结果、期限、可用时间/资金、不能承担的后果；哪些已由用户决定 |
| 假设（Assumptions） | 方案成立所依赖的机制假设，写成可观察的陈述；区分事实、用户报告、推断和未知 |
| 反证（Falsifiers） | 什么观察出现就说明假设错了；至少保留一个竞争解释 |
| 预测（Predictions） | 指标口径、单位、方向、基线、观察窗口、数据来源；可给概率时写主概率 p 与基准 p0；不能可靠给概率时保留定性判断 |
| 停止条件（Stop conditions） | 风险上限、预算、复盘节点、停止/撤回/加码/升级条件 |

同时比较可行路线与“维持现状”，不把 AI 偏好的路线冒充用户选择；未被采纳的方案标为“建议”。

## 二、分析怎样才算完成

分析输出同时包含：事实边界、价值目标、主体条件（资源、能力、授权）、因果假设、竞争解释、可实施接口、基准与备选方案、取舍依据、风险边界、执行计划和反馈安排。

可按以下模块组织（不适用的模块写“不适用”及理由，不编造内容）：

1. 界定问题与期限
2. 世界结构与约束（查现场，不用旧状态替代现状）
3. 主体、资源与站位
4. 价值、目标与底线
5. 所需能力与结构
6. 接口与他方可能反应
7. 竞争假设与因果审计（追原始来源，同源只算一个证据组）
8. 候选杠杆
9. 信息价值、行动价值与风险（可逆性优先）
10. 行动阶段与治理（谁授权、谁执行）
11. 观察、归因、校准与演化

不能唯一排序时，写明推荐依赖的价值选择或关键未知，并给出具体的信息获取动作、最小承诺或明确的等待决定及期限。不得用“继续研究”替代具体动作，不得为了填满而伪造数字。

## 三、冻结前检查

1. 分析版本与信息截止时间明确。
2. 选中方案和可执行动作明确。
3. 指标口径、基线、窗口和数据来源已处理；缺项说明为何不影响当前动作。
4. 风险上限、预算、复盘节点、停止与升级条件明确。
5. 执行人、决定人和授权范围明确；建议与已采用决定不混淆。
6. 关键预测在结果揭晓前登记。
7. 快照已保存到可回读的位置。

行动已经发生再补记录的，如实标“事后补录”，不获得事前预测的证据资格。

## 四、执行与观测

先记录原始结果，再写解释。每条观察至少保留：发生时间、记录时间、对应方案、实际动作或指标、数值与单位、来源、质量状态。更正时新增记录指向原记录，不删除原记录。外部操作结果未知时先对账，不重复提交。

## 五、复盘顺序

核对数据与执行 → 按**原**目标计算达成情况 → 检查反事实与竞争解释 → 区分随机波动、执行偏差、环境变化、机制错误与目标不适配 → 再评价当前价值与后续行动。

结果状态可用：达成／部分达成／未达成／未到期／无法判定。因果状态可用：观察到变化／机制支持／有限因果支持／证据不足。一次负结果不自动否定机制，一次正结果不证明方法普遍有效。

## 六、更新与规则沉淀

每次复盘形成一条更新记录（包括“保留不变”）：旧值、新值、依据、影响范围、决定人、生效时间、下一次验证。需要改变行动时先形成新版本方案并保存快照，再切换“当前方案”指针。

经验升格为规则不按成功次数自动发生：审查证据独立性、失败记录、反例、环境差异和相对基准的价值；规则写明适用范围与复核条件。

## 深度分级

简单、低后果、可逆的事项可用轻量路径，但要说明省略了哪些模块及原因。高后果、不可逆或目标冲突的新问题使用完整分析。已经冻结策略下的日常子动作只登记真实增量。

## 四类有效性分开检查

概念有效、经验有效、程序有效、规范有效分别判断。日志完整不证明结果改善；格式不能代替判断。
