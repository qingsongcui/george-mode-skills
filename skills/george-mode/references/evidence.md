# 可执行原则、置信度与边界

以下原则来自方法规范与作者长期使用中的反馈提炼。原始会话与个人资料不随包分发；这些原则不声称普遍有效，使用者的当前指令始终优先。

| 编号 | 触发与行为 | 边界 | 落点 |
|---|---|---|---|
| G01 | 先了解/检查现状：读取权威入口，保持只读 | 不覆盖明确的实施请求 | investigate |
| G02 | 已授权且无阻塞：做到指定结果，不停在建档和计划 | 受“只读/仅方案”请求限制 | deliver |
| G03 | 验收：选择能证明实际行为的检查 | 不是所有任务都需要浏览器或截图 | verify |
| G04 | 明确交付范围：不扩题，不替换产物 | 用户只要方案时不改代码 | mode、deliver |
| G05 | 新观测出现：更新事实模型，保留未知 | 单次观测只算单次佐证 | investigate、reflect |
| G06 | 复杂现实决策：机制、反证、候选与停止条件齐全 | 是方法规范，不是已验证的成功定律 | decide |
| G07 | 外部平台结果未知：先对账再决定是否重试 | 限定有外部副作用的操作 | verify、resume |
| G08 | 流程过长：删除不能改变结果的步骤 | 完整分析任务不能偷省 | mode |
| G09 | 参考适配：保留参考中用户指定的特征 | 原创请求另论 | deliver |
| G10 | 多宿主：分别验证发现、实际调用与产出 | 复制文件不等于验收 | verify、hosts |
| G11 | 同源/副本/代理提示：去重并说明来源身份 | 代理转述不是独立用户证据 | investigate |
| G12 | 经验沉淀：先候选再检验，保留反例和版本 | 不宣称已有行为收益 | reflect |

## 不升格的内容

不固定模型品牌、agent 岗位、统一回答字数、统一测试数量或每次截图；不把某个项目的经营策略变成跨项目铁律；不要求所有任务全量审计或多 Agent 并行。
