# George mode 0.3.0 使用与验收

按需调用、按任务轻重分层。理论、个人证据原则、完整工程流程与可运行工具在同一包内；使用 George 时不必另装 pstack。

## 宿主调用与发现

各宿主共享同一份技能源目录，默认显式按需调用：

- **Codex**：输入 `$george-mode` 加任务，或从技能菜单选择；
- **Cursor**：输入 `/george-mode` 或在技能菜单选择；
- **OMP**：原生命令为 `/skill:george-mode`，或从技能列表选择；安装脚本亦提供 OMP 专属 `/george-mode` 文件命令别名。
- **Grok CLI**：输入 `/george-mode`；发现已安装的 `~/.agents/skills/george-*`，可用 `grok inspect` 核对。
- **Antigravity**：输入 `/george-mode`（支持 Antigravity 2.0、IDE 与 `agy` CLI）；发现已安装的 `~/.gemini/config/skills/george-*`，可用 Language Server `GetAllSkills` 核对。
- 若菜单未出现，可指定 Agent 读取技能入口 `SKILL.md`，手动读取不等同原生发现。详细执行差异与配置参见 [宿主适配](hosts.md)。

例：`使用George mode修复这个问题，按真实入口验证。` 已定方案直接推进；仅要解释/计划就交该产物。复杂任务自动按实际风险接设计竞争、独立审查、评测和编排；简单任务保留相关验收，不强制全套理论或多人。

OMP 0.3.3 启用时先实际读取 [OMP自主调度](../../george-orchestrate/adapters/omp.md)。Grok 0.3.4 启用时先实际读取 [Grok自主调度](../../george-orchestrate/adapters/grok.md)。Antigravity 0.3.5 启用时先实际读取 [Antigravity自主调度](../../george-orchestrate/adapters/antigravity.md)。当前 George 会话后续每个任务由主控自动决定是否委派及职责、模型、强度、并发、预算与恢复，不要求用户选技术参数；小任务仍直接完成。此合同不成为全局常驻规则，也不扩大外部操作权限。

OMP 角色请求值不等于实际运行值，须逐 worker 核对；硬取消、parked 复活与后代进程回收以当前宿主实测为准。

## 交付包

运行所需方法、宿主适配器和工具均在本包中，不依赖作者私有资料。历史宿主验证不能证明当前安装环境可用，安装后按本机能力重新验证。

## 验收状态

- 本地 11 个模块共享同一源；安装链接存在、宿主加载与真实任务成功分开验收。不能把一个宿主的成功推广为其他宿主通过。
- 状态、计划、验证运行器与 GitHub watcher 的回归测试在 `tests/` 与 `tools/pstack/watch-pr/*.test.ts`。
- 帮助导航采用宿主安全的相对链接，消除旧软链接引起的跨宿主断链与跳过检查漏洞。
- Codex 保持 `$george-*` 与 `agents/openai.yaml`；Cursor 保持 `/george-mode`；OMP 保持 `/skill:george-mode` 与专属命令别名；Grok 保持 `/george-mode` 与 `adapters/grok.md`，不另装 `~/.grok/skills/george-*`；Antigravity 保持 `/george-mode`、`~/.gemini/config/skills/george-*` 与 `adapters/antigravity.md`。各宿主现有模型与凭据配置保持不变。

## 安装、维护和回退

安装操作从解压后的包根目录进行，不是从当前业务项目或本文件目录进行。先读包根目录 PORTABLE.md。运行 `python3 scripts/install.py` 预览，`--apply` 安装；已有同名路径拒绝覆盖。卸载时 `--remove --apply` 只移除指向该包的链接。

独立包运行 `python3 scripts/verify_package.py` 检查文件完整性和必要资源；它不证明宿主模型服务可用。`python3 -m unittest discover -s tests` 运行包内回归测试。
