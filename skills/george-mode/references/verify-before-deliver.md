# 先验证、后交付（自包含参考）

本页定义 george-mode 的执行与验收底线，适用于所有模块。

## 开工前

1. 写下本轮交付物、允许操作的范围和“完成”的证据形态。
2. 读取当前工作区的规则文件（如 AGENTS.md）与权威入口，检查已有修改和未结事项。
3. 区分只读请求（“先了解”）与执行请求（“修复、继续、执行”）：前者只读不改，后者做到可验收结果。
4. 缺失事实先自行查证；只有会改变目标、不可推断的偏好或缺失授权才提问，等待时继续做可逆的独立工作。

## 授权边界

- 授权只覆盖指定对象、操作和范围。技能本身不能替用户授权发布、支出、对外消息或全局配置变更。
- 不顺手修改无关配置；保留用户选择的产品、目录、模型和工作流。

## 验收层级（分别报告，不相互替代）

| 层级 | 说明 |
|---|---|
| 文件存在 | 产物已生成在约定位置 |
| 静态检查/测试通过 | 能证明行为的检查已运行 |
| 真实运行 | 在真实宿主或真实数据上跑通并回读 |
| 平台生效 | 外部系统中的状态已回读确认 |
| 用户采用 / 结果形成 | 只有出现真实反馈才可声称 |

选择能证明实际行为的检查，而不是最容易通过的检查。用户要成品就检查成品本身，不能只交制作脚本。

## 失败处理

连续失败时回到共享前提与首个失败环节，不用同一条件无限重试。外部操作结果未知时先对账，再决定是否重试。

## 收尾

先说结果，再给实际证据与未完成项；把事实、推断、预测和未知分开。
