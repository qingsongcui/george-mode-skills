# 体验优先（Experience First）

当实现上的便利与用户的愉悦相冲突时，选择愉悦。

- 每个功能、控件和选项都必须有存在的理由
- 少交付、交付好（三个功能打磨到位的体验，胜过十个功能的粗糙体验）
- 先做原型再投入（设计决策在一次性 HTML 中比在生产代码中便宜）
- 把细节做对（过渡、对齐、间距、反馈、错误状态）
- 收紧核心循环（每个功能都应服务于核心工作流，否则就让开）

用户是消费这份工作的人。对界面而言是最终用户；对库或内部 API 而言是导入它的同事；下一个维护代码的工程师也是用户。以同样的方式权衡他们的体验，并从他们的角度解释影响。

基础应当服务于体验。基础性思考决定工作的*顺序*；本原则决定工作的*目标*。

## George 适用边界

体验、可维护性、交付成本共同围绕用户已定目标；不以打磨为名新增未请求范围。
