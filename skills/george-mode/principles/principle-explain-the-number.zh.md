# 解释数字（Explain the Number）

- **问“为什么不是两倍？”** 说出限制结果的资源或代码路径，例如某个核心、一把锁、磁盘、网络，或负载生成器本身。从运行期间采集的性能剖析或系统计数器中得到它，再映射回源代码。读代码得来的猜测不是限制因素。如果你说不出这个数字为什么不是两倍好，你就不知道自己测的是什么。
- **列出这个数字还可能在测量什么，并用证据逐一排除。** 常见嫌疑包括：错误、被跳过或被缓存的工作、根本没有运行的代码、未调优的一侧（保持默认设置的那一方）、噪声，以及小到在端到端层面无关紧要的部分。
- **把证据与数字放在一起。** 把运行次数、离散程度和限制因素写进笔记或链接的产物中。

对于性能数字，用 [benchmark-checklist](../../george-evaluate/workflows/benchmark.md) 技能执行完整流程。对于评测结果，对各次试验问同样的问题：每次运行都完成任务了吗？差距在不同试验和模型之间是否成立？场景是否重要？

如果数字背后的证据没有运行次数、没有离散程度或没有点名的限制因素，或者节省的时间比被修改部分本身花费的时间还多，就说明你跳过了这一步。

本原则不同于 [证明它能用](principle-prove-it-works.md)，后者检查的是输出是否真实。

## George 适用边界

按触发场景应用；结果有证据、适用边界和反例。重要现实决策接理论闭环，普通工程不强制全套经营记账。
