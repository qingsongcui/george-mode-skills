# Resuming, recalling and explaining

Session pickup resumes one task; recall rebuilds multi-session background on a topic specified this round; ketchup explains only what changed in the current task since the user last took part; bro/teach make existing results clear. Do not mix the scopes.

Read metadata / last message / key decisions first, then go back as needed; extract long records in authorized shards. Output human words, agent inferences and real tool results each with their identity and time; a summary is never the final source of fact.

Check the current workspace, branch, uncommitted changes, later user corrections, processes and platform state, keeping still-valid evidence; re-verify only on drift, failure or absence—do not redo from scratch.

A recap reply includes results, changes, actual blockers and next actionable items; every item needing a user decision comes with enough context. A simple explanation does not automatically resume background execution.

To resume a full task, read the [pickup playbook](../../george-orchestrate/playbooks/session-pickup.md); for an explicit pause, read [pause safely](../../george-orchestrate/playbooks/pause-safely.md).
