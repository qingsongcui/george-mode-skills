# Evaluation methods and skill improvement

> English translation of [SKILL.md](SKILL.md). Hosts load `SKILL.md`; this file is the full English body.

First determine which specific claim is being verified:

- Whether a mode/prompt/model/structure changes behavior: [blind testing](playbooks/eval.md).
- Whether a performance or efficiency number is credible: [measurement audit](workflows/benchmark.md).
- Creating or reworking a skill: [skill authoring](playbooks/authoring-a-skill.md).
- Continuous improvement from personal habits and failures: [mode improvement](../george-reflect/workflows/improve-mode.md).

Evaluations must keep failures, repetitions and limitations. Static structure checks, real-scenario checks, cross-host task performance and improvement relative to Poteto are different claims, each needing its own evidence; one cannot be inferred from another. Use the explain-the-number, behavior-testing and real-verification leaves in [engineering principles](../george-mode/principles/INDEX.md).
