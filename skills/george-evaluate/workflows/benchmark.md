# 解释一个测量数字

1. 先写准备报告的主张、指标、单位、方向、现实工作负载和失败判据，读测量脚本确认计时边界及统计量。
2. baseline与处理组使用同硬件/限制、相同工作量和结果要求，双方配置合理，不比较一边默认另一边特调。确认实际路径执行、结果正确、错误/丢弃/重试数量。
3. 正式比较至少交替五轮，预热与冷/热缓存策略固定，记录原始值、样本数、中位/范围或合适分布。用户只需粗估可单轮但标粗估，仍查错误和工作完成量。
4. 捕获profile或系统计数器找真实限制：CPU、锁、磁盘、网络、负载发生器。用证据解释“为何不能再快一倍”。微基准节省不可能超过该环节原有时间，需回到端到端影响。
5. 排除缓存、跳过工作、错误响应、噪声、不等负载、采样偏差及不代表真实使用的极端。测量器不能区分负载就不能用它优化。
6. 输出更快/更慢/无差异/不确定。瓶颈不明、任一侧未公平配置、成功输出未确认时，保留不确定，不能只挑最好一轮。

Agent评测同样检查所有试次实际做了任务、失败是否被排除、差异是否跨重复/模型保持、场景是否代表用户工作。
