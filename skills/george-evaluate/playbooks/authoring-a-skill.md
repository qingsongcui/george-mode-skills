# 技能编写与更新

1. 先读适用 skill-creator，明确触发与不触发、输入、不可丢步骤、产物与通过条件。来源技能逐能力映射，不把摘要视为等价实现。
2. 将稳定规则放入口，长流程放按需引用，确定性动作做可重跑脚本。保留原来源、版本和改造原因；引用均指向包内实际文件，不依赖原技能仍安装。
3. 用户已要求创建或修改则直接实施；其他业务复盘只提出改进，不擅自全局写记忆。新规则说明适用边界、反例和移除条件。
4. 验证 frontmatter、内部链接、脚本、依赖、安装不覆盖，以及从总入口到叶子和工具的可达性。
5. 用 [盲测](eval.md) 或独立真实任务验证行为，涉及结构安全至少包含会失败的反例。记录实际读取与产物；静态检查不能代替行为评测。
6. 新旧版本对照完成后发布到本地技能源，保留回退快照，更新矩阵与版本哈希。跨宿主逐层记录安装/发现/执行证据。仅任务需要才创建 PR。
交付：具体变化、能力覆盖、真实验收、未验证能力。
