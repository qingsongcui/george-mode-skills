# Investigation and modeling

> English translation of [SKILL.md](SKILL.md). Hosts load `SKILL.md`; this file is the full English body.

First list questions and evidence objects, find the project's authoritative entry points and original sources, then extract conclusions. File counts, chat counts and successful tool returns are not business results.

For history mining, first list sources, time window, number of sessions, number parseable, number actually read and reasons for omissions. Extract real user utterances stratified by host, project and time, excluding system prompts, AGENTS injections, forwarded text and sub-agent prompts; deduplicate copies of the same session. Keep the original file with line numbers or database keys, store only necessary short quotes, and filter out secrets and unrelated customer data.

Classify experience as current explicit requirements, preferences supported by repeated observation, one-off situational preferences, and hypotheses to be verified. Repeated support must come from at least independent sessions, and contrary cases must be checked. Two agents restating the same conversation does not raise confidence.

When investigating business matters, first unify window, units, objects and attribution basis; write the mechanism chain and at least one competing explanation. When evidence is insufficient, state the unknown explicitly rather than filling with adjectives. Read-only tasks deliver an evidenced answer and do not automatically move into development or external operations.

The output should answer: what was read, what was found, what was not read, and which evidence would overturn the conclusion. When a decision is needed, go to [george-decide](../george-decide/SKILL.md).
