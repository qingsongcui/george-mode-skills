# 多阶段计划交付

用户仅要计划时，这份计划就是产物；不实施、不创建执行队列或发布。用户已明确要求边计划边做时，不重复索要go。

1. 读取目标与现状，确认需要计划。显然一两文件的小改不强制大表。关键事实未知先做只读验证或隔离原型，保留原型证据。
2. 每一单元写：id、依赖、所有权、文件范围、实际交付物、用户可见行为、执行剧本、行为检查、真实表面验证、性能适用性、审查门、回滚/停止及交付方式。
3. 每个勾选项有证据路径和通过谓词。unit/live/perf适用性分别写；不适用有理由，重要真实行为不能被“只跑单测”替代。验证lane按风险覆盖，固定十条不再是要求。
4. 检查DAG无环、文件所有权不冲突、前置先验、每个单元结束可验。计划中的事实与待决定项分开。
5. 用 [计划检查器](../tools/check_plan.py) 验证 [结构模板](../templates/plan.json)。检查器只审结构/依赖/证据定义，不能证明实际行为或计划质量。
6. 交付计划、关键选择、原型证据、检查结果和执行边界。只产计划的请求到此结束。
