# Long-term project coordination

Entry condition: cross-session, multi-phase, multi-person, multi-artifact work needing ongoing coordination; if a single agent can finish within this round, converge to a specific playbook.

1. Write the project contract: countable completion predicate, scope/exclusions, budget, phases, owners, independent verifiers, authorization boundaries, stop conditions, real acceptance and recovery points. Link important real-world decisions to the George theory loop; do not reopen analysis for settled routine implementation.
2. Build a persistent workbench and manage units, inbox, gates, frontier, ledger and standing with the [state tools](../tools/README.md); persistent facts do not live only in chat. The root coordinator is the sole writer of topology and aggregate state; workers write their own artifacts and independent messages.
3. Run a pilot: take one unit through understand → implement → real acceptance → independent review → delivery or pending authorization, confirming the tools and evidence chain work before scaling. On errors, fix the shared process first; never scale a failure.
4. Build the DAG, completing prerequisite shared contracts first; each unit has one owner and an independent write area; the brief includes sources, acceptance, commands, time limit, allowed operations, no-edit zones, report path, current version and later user corrections. Never let a sub-agent take over the whole main task.
5. Open a rolling window by real independent artifacts and available slots, refilling one as one completes. The root stays responsive and does not open more than the budget can review; reserve integration and acceptance cost; stop adding assignments as the budget nears.
6. Read the inbox at phase boundaries/completion events. Reading does not delete; after successful handling is written back to unit/ledger, ack to archive, so it can be reread after a crash. For PASS verify the artifact, version and independence; fix ISSUES; for BLOCKED distinguish permissions, environment, upstream and implementation.
7. For no artifact or a dead worker, first check the actual process/agent end state, last evidence and ownership. Change owner only after confirming it stopped, with the full brief, uncommitted work and failure reason. For repeated similar failures, review the shared premise first; never let two owners write at once.
8. Propagate user pauses/goal changes to everyone affected; reconcile unknown external actions first. Gate defaults or timeouts never create authorization; an undecided product choice does not block independently doable items.
9. Implementation complete and mergeable are separate. A head change invalidates old verdicts; new CI and real behavior evidence are verified separately. The delivery chain is maintained by the topology owner; writers are frozen once in Shipping.
10. At wrap-up, check all units, all agent end states, processes/worktrees, latest version evidence, pending gates and the real completion predicate. Keep uncovered or failed items explicitly, stop monitors created by this task, and produce a cold-startable checkpoint.
Artifacts: workbench, dependency and ownership table, evidence ledger, decision trail, done/remaining/stop reasons.
