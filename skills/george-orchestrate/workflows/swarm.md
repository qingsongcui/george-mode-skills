# 分区并行、竞赛与验证矩阵

1. 先写可判完成谓词，选择分区覆盖、同任务竞赛或交叉检查。分区用互斥输入/文件；设计竞争交给george-design的arena。
2. 按风险列覆盖矩阵，字段为功能/边界/数据状态/平台/预期/证据/负责人。人数由独立产物、预算和宿主槽位决定，不机械十人或固定模型。
3. 每个worker收到同一已固定合同、实际head/输入哈希、owned路径、禁改区、运行命令、时限、回报路径；明确并非唯一写入者，不能回退他人工作。写操作隔离worktree或目录。
4. 回报PASS/ISSUES/BLOCKED、执行命令、实际产物和版本。主代理亲自核查输出，覆盖缺口不能算PASS。最多一次无根因的重派；再次失败先查共同前提。
5. 竞赛事前定选择标准、终止条件和剩余worker的处置。预算接近上限先停止新派发，归并并验证已有产物，不放任孤儿进程。
6. 协调者维护覆盖表，处理共享状态与集成；报告未覆盖及掉队。不同代理读同一资料不能算独立来源。
