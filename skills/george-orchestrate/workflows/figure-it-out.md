# 定制复杂任务流程

适用于没有现成剧本、跨很多调用者的迁移或复杂交付；单个常规任务用专用剧本，跨日项目用orchestrate。

1. 明确用户可见完成谓词、范围、授权、预算、风险和不能破坏的行为。识别最大未知，把廉价高信息验证放在前面。
2. 先理解系统，再建立真实产物的验证基线。必要时原型解决事实分歧；重要取舍进入george-decide。
3. 设计阶段、依赖、所有权、产物、验证、恢复条件。每阶段可检查，不能用“完善”“优化”当完成标准。
4. 先跑一段pilot验证工具/流程，再推广。优先确定性脚本而不是让很多代理重复手工操作；每个单位改完即验。
5. 持续写 [决策轨迹](decision-trail.md)，证据反对就转向并保留撤销记录。INCONCLUSIVE不是通过，预算耗尽如实保留剩余项。
6. 做最终真实交付验收与独立复核，报告完成谓词的实际状态。
