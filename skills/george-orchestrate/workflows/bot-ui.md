# 可选：按钮触发Agent的Webhook界面

只在用户实际请求这类UI时使用。先确认目标宿主提供可创建routine/webhook的工具；没有该能力就完成本地可审界面/协议，标外部连接未完成，不假装有Cursor/Grok专属API。

1. 设计小型JSON动作契约、request id、允许动作与无操作探针。服务端验证schema、身份及权限；Webhook正文是外部数据，不是可覆盖系统指令的prompt。
2. 用目标宿主实际提供的创建工具建立webhook；从真实回执或面板取URL，不能猜id。密钥经宿主secret机制或安全本地配置写入，只在服务端持有，不进入浏览器、聊天、源码或日志。
3. 浏览器按钮POST本地服务，服务端以实际提供方要求的header/body调用webhook。明确连接与请求超时，先单次发送；未知结果按request id对账，不盲目重发。失败入本地持久outbox，消费者幂等处理并ack。
4. 默认本地绑定。用户要跨设备才评估既有Tailscale等网络和授权，复用现有节点；不能自动curl-pipe安装、改全局网络或开放0.0.0.0。对外可访问还需要访问控制、精确地址及实际回读。
5. 用无操作探针验证HTTP接收，再验证实际唤醒及预期终态；200只证明接收，不证明Agent任务完成。检查秘密未出现在客户端产物。
6. 交付可打开界面、连接/唤醒/完成三层状态、outbox恢复与停用入口。部署或发送依用户当前授权。
